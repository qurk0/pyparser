# Проект: Импорт и обработка данных об успеваемости студентов

## Описание
Приложение для импорта данных об успеваемости студентов из HTML- и CSV-отчетов в PostgreSQL с последующим расчётом результатов и рейтинга студентов.

Проект реализует полный цикл обработки данных: парсинг исходного отчёта, нормализацию данных, сопоставление с существующими сущностями БД, сохранение версионированного снимка оценок и пересчёт текущих результатов студентов.

## Возможности
1. Импорт отчетов в форматах HTML и CSV;
2. Приведение разных форматов входных данных к единой модели;
3. Нормализация оценок и форм контроля;
4. Работа с учебными планами, дисциплинами и формами контроля;
5. Сохранение версионированных снимков оценок;
6. Расчет суммарного и семестрового балла;
7. Расчет процента от максимального результата;
8. Распределение баллов по кафедрам;
9. Определение незакрытого семестра;
10. Расчет изменения результатов относительно предыдущего импорта;
11. Построение текущего рейтинга студентов;
12. Обновление рейтинга через PostgreSQL UPSERT;
13. Атомарный импорт данных с откатом транзакции при ошибке.

## Архитектура обработки данных

Парсеры HTML и CSV возвращают единую модель ParsedReport, поэтому дальнейшая логика импорта не зависит от формата исходного файла.

Одна запись ra_version соответствует одному полному снимку оценок из импортированного отчёта. Оценки конкретной версии хранятся в ra_mark.

ra_results содержит актуальное рассчитанное состояние рейтинга. При повторном импорте существующая строка студента обновляется через INSERT ... ON CONFLICT DO UPDATE.

## Транзакционность

Один импорт выполняется в рамках одной транзакции PostgreSQL.

Если на любом этапе возникает ошибка, выполняется ROLLBACK, поэтому частично импортированные данные не сохраняются.

Управление транзакцией находится на уровне основного сценария приложения, а функции слоя работы с БД не выполняют самостоятельный COMMIT.

## Установка
Клонировать репозиторий и перейти в его директорию. 

Создать виртуальное окружение.

Установить зависимости:
`pip install -r requirements.txt`

Создать локальный .env:
`cp .env.example .env`

Пример конфигурации:
DB_NAME=mydb
DB_USER=myuser
DB_PASSWORD=change_me
DB_HOST=127.0.0.1
DB_PORT=5434

Для запуска необходимо запустить PostgreSQL:
`make start`

Далее загружаем исходные данные из дампа:
`make seed`
Этот этап необходим, так как содержит заранее заготовленные данные (подробнее об будет сказано в разделе "Особенности модели данных").

Для импорта данных:
`make load file=report.html`
или
`make load file=report.csv`

Остановить PostgreSQL:
`make stop`

Повторно запустить остановленный контейнер:
`make restore`

Полностью пересоздать БД:
`make reset`

Создать дамп:
`make dump`

Загрузить данные, считающиеся существующими:
`make seed`

Список доступных команд:
`make help`

## Тестирование

Запуск тестов:
`pytest -q`
или
`pytest -vv`

Тесты проверяют в частности:
- парсинг данных из отчётов обоих форматов
- нормализацию входных данных
- расчет результатов
- расчет изменения рейтинговых показателей
- создание полного снимка оценок
- обновление существующих результатов
- отсутствие дублирования результатов студентов
- откат всей операции при ошибке во время импорта

Интеграционные тесты выполняются внутри транзакций и откатывают внесенные тестовые изменения после завершения тестирования.

## Особенности модели данных
При импорте отчета, по условию задачи, приложение предполагает, что информация о студентах, группах и студентах уже существует в БД. Импортер сопоставляет данные отчета с существующими записями и не создает эти сущности автоматически.

В репозитории есть файл dump.sql, содержащий в себе данные, необходимые для работы приложения. В нём уже есть записи о студентах, группах и дисциплинах, которые считаются уже существующими.

Основные данные импорта сохраняются в таблицы:
- ra_plan - учебные планы;
- ra_control - формы контроля;
- ra_version - версии импортированных данных;
- ra_mark - оценки конкретного снимка;
- ra_results - актуальные рассчитанные результаты студентов.
